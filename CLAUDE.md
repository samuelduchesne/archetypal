# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Create, translate and codify building energy archetypes on SBEM.

This project uses:
- **uv** for dependency management
- **Ruff** for linting and formatting
- **pyright** for type checking
- **pytest** for testing
- **MkDocs** for documentation

## Common Commands

```bash
# Install dependencies
uv sync

# Run all quality checks (lint, format, type check, deptry)
make check

# Run tests
make test

# Run a single test
uv run pytest tests/test_file.py::test_function -v

# Serve documentation locally
make docs
```

## Project Structure

```
src/archetypal/    # Main package
tests/              # Test files (mirror source structure)
docs/               # MkDocs documentation
pyproject.toml      # Project configuration and dependencies
```

## Skills to load

- **Code that imports idfkit.** Before writing or changing any module or test that imports `idfkit`, load
  `/idfkit:developing-with-idfkit`. It finds the idfkit installed in `.venv` (after `make install`) and loads the
  reference pages for that exact version. Read the smallest reference page that covers the task.
- **Documentation pages.** Write or revise every page under `docs/` with `/project-kit:diataxis`: name the mode first,
  read that mode's reference, brief the `project-kit:editor` agent with verified facts, run the mode's failure
  checklist, and wire the page into the `mkdocs.yml` nav.
- **Template upkeep.** Update the files generated by the template with `/project-kit:upgrade-project`; never re-create
  them by hand. `.cruft.json` links the project to the template.

## Branches and releases

- **`v2.x`** holds archetypal 2 (poetry, Sphinx, Read the Docs). It receives security fixes only and releases
  `2.18.x` patches. archetypal 2 work never goes to `v3` or `main`.
- **`v3`** is the integration branch for archetypal 3 until milestone M1. CI runs on pushes to `v3` and on pull
  requests into it.
- **`main`** holds archetypal 2 unchanged until M1, when `v3` is merged into it; from then on `main` holds v3.
- **Milestones** are GitHub pre-releases on tags `v3.0.0aN`. They deploy the docs; the publish job skips them, so
  nothing reaches PyPI before v3.0.0, a normal release cut once upstream releases what archetypal needs.

## Code Style

- **Line length**: 120 characters
- **Imports**: Always include `from __future__ import annotations`
- **Type hints**: Required on all functions (parameters and return types)
- **Docstrings**: Google or NumPy style for public APIs
- **Data models**: Use dataclasses or Pydantic instead of raw dicts

## Testing

Tests live in `tests/` and mirror the source structure. When adding new functionality:

1. Create test file: `tests/test_<module_name>.py`
2. Write tests before or alongside implementation
3. Run tests: `uv run pytest tests/test_<module_name>.py -v`
4. Verify all tests pass: `make test`

Use pytest fixtures (in `conftest.py`) for shared test setup.

## Type Checking

This project uses **pyright** for static type analysis.

```bash
uv run pyright
```

Ensure all new code is fully typed. The configuration is in `pyproject.toml`.

## Before Committing

Always run the full quality gate before proposing changes:

```bash
make check && make test
```

This runs: lock file validation, pre-commit hooks (ruff format/lint), pyright, deptry, and pytest.

Add an entry under `## [Unreleased]` in `CHANGELOG.md` for user-facing changes, using the Keep a Changelog categories (Added, Changed, Deprecated, Removed, Fixed, Security). Create the category heading if it is missing, and skip internal-only changes (refactors, tests, CI):

```markdown
## [Unreleased]

### Fixed

- Handle empty input in `load_config` instead of raising `KeyError`.
```
